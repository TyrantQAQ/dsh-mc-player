# dsh-mc-player

让 AI 像一个**真实玩家**那样活在 Minecraft Java 版里：会走会跳会怕，会自己定目标，会手滑也会自救；做完事能拿出证据，而不是说"应该做好了"。

设计文档在 [docs/design.md](docs/design.md)，这里是它的实现。

## 安装

1. 装好 [DSH](https://deepseek.com) 桌面版（或 dsh 命令行）。
2. 装这个 bundle：DSH 的安装器支持 git 地址的话，直接装 `git+https://github.com/TyrantQAQ/dsh-mc-player.git`；只接受本地目录的话，先 `git clone` 再装这个目录。依赖由安装器装。
3. 26.2 数据不用手动管：插件启动时会自检，缺了就自动从 `vendor/26.2` 补装（`npm run setup:26.2` 是手动兜底）。
5. 重启 DSH；设置 → **MC 玩家**，填地址/端口/版本，点「连接」。
6. 之后在游戏聊天框里说话就能指挥它；模型那侧有 27 个 `mc_*` 工具。

要求：Node ≥ 22；26.2 需要 Java 25 的服务端；其他版本走 minecraft-data 自带的数据（26.2 是随包 vendor 的）。

---

## 为什么不用现成的

`whale-craft`、`dsh-mc-agent` 把每个动作做成一次工具调用，调用结束才把结果交给模型。三个问题：

1. **动作期间模型是瞎的** —— 挖矿跑十秒，这十秒里僵尸来了它不知道。
2. **每次都太准** —— 追求成功率反而不像人。
3. **只做事，不过日子** —— 没有"今天想干什么"。

这个插件的核心是把**反射**和**判断**分开。

## 小脑 + 大脑

```
大脑（DSH agent）     决定打不打、去哪、盖什么、今天做什么        秒级
   ↓ 工具调用（一个动作）
小脑（本插件，20Hz）  保命反射、感知、执行、回读、事件攒着
   ↓ mineflayer
Minecraft 服务器
```

小脑**不替大脑做决定**，只做几件保命的事：

| 条件 | 动作 |
|---|---|
| 掉进岩浆 | 放水桶（有的话）/ 上浮 |
| 头卡进方块 | 随便挪一个方向挣出来 |
| 氧气 ≤ 8 且在水里 | 上浮 |
| 苦力怕 ≤ 4 格 | 转身、后退 0.7 秒、有盾举盾 |
| 血 ≤ 6 且背包有吃的 | 掏最好的食物吃 |
| 3 只以上怪围上来 | 停手，报事件 |
| 血 ≤ 12 还在挨打，怪就在 5 格内 | 停手、后退、报事件（空手被一只史莱姆打死过，加的） |

命中时**立刻打断正在进行的动作**（`pathfinder.stop()` / `stopDigging()`），不等模型。
判定逻辑是纯函数，假 bot 就能测（见 `scripts/selftest.mjs`）。

## 装

```bash
# 本机依赖（mineflayer / pathfinder）
cd mc-player && npm install

# 挂进 DSH profile（会把本目录 link 进 profile）
dsh plugin --profile desktop add link:$(pwd)
# 或者让 agent 调 plugin_manager install_bundle，target 传本目录绝对路径
```

装完在插件列表里能看到 **MC 玩家 / MC Player**，工具名以 `mc_` 开头（27 个）。

## 用

```
mc_connect                       # 上线（默认 127.0.0.1:25565，离线账号）
mc_status                        # 我在哪、什么状态、周围有什么、攒了什么事件
mc_move  {place:"home"}          # 回家
mc_mine  {block:"stone",count:20}
mc_craft {item:"stone_pickaxe"}
mc_build {blueprint:{...}}       # 图纸 → 算料 → 施工 → 验收
```

地址/账号可以在 `mc_connect` 里改，会存到 `$DSH_HOME/mc-player/config.json`。
记忆（家、矿洞、死亡点、目标、施工进度）在同目录 `<host>_<username>.json`。

### 放置：参考面与朝向

放一块东西，服务器只做一件事：从眼睛射线过去，看你点中哪块、哪个面，把方块放到那个面的外侧格。所以**参考方块不必是整块**——半砖、台阶、栅栏、墙、铜格栅都能当垫面，只要点击点落在真实碰撞面上。`lib/placement.js` 会按 `block.shapes` 算出那个点，再验一遍射线确实打在这块上。

朝向按方块家族查规则表（都是 1.16.5 实测出来的，机制到今天没变）：

| 家族 | 朝向由什么决定 | 例子 |
|---|---|---|
| 楼梯 | 你的视线方向 | `{facing:"east", half:"top"}` |
| 半砖 | 点在侧面的上半还是下半 / 上方那块的底面 | `{type:"top"}` |
| 原木 | 点哪个面就是哪个轴 | `{axis:"x"}` |
| 箱子/熔炉/活塞/发射器 | 背对你 | `{facing:"north"}` |
| 侦测器（观察者） | 眼睛朝你视线方向，红石从**反面**出 | `{facing:"west"}` → 信号朝东 |
| 漏斗 | 管子伸向的容器；默认朝下，点侧面就朝那个面 | `{facing:"east"}` → 灌进东边的箱子 |
| 火把/梯子/拉杆/按钮 | 贴哪面墙，朝向就是离开墙面的方向 | `{facing:"west"}` |

规划器会自己算：站到哪一侧、点哪块的哪个面、点面上哪一点；站不到那个位置会直接说缺什么，而不是瞎放一堆错的。

几个容易搞反的：

- **侦测器**的 `facing` 是"眼睛"（观察面）朝哪，红石脉冲从反面出。要它把信号往东打，就设 `facing:"west"`；你站在它前面放它，红点那面（输出）朝你。
- **漏斗**的 `facing` 是管子伸向的方向，也就是它把东西灌进去的容器。要连到东边的箱子就 `facing:"east"`，放的时候会贴着那个容器（遇到箱子会自动潜行，不会打开它）。漏斗的取料永远从**正上方**的容器拉，灌料往 `facing` 那面推；朝上的漏斗不存在。
- 箱子和侦测器都有"贴面"问题：在可交互方块旁边放东西，不潜行就会打开它——插件的规划器会自动潜行。

### 返回值约定

```json
{ "ok": true, "verified": false, "summary": "…", "evidence": {…}, "hint": "…" }
```

- `verified: true` 才算真做成。
- `verified: false` 是**做了但回读不对**——比如挖完了那格还是方块、放了但变成别的。
- `verified: null` 是没法验证（指令、右键、喂食）。
- 事件不跟着每个动作走，只在 `mc_status` 里一次性给，给完清空。

## 动作怎么回读

| 动作 | 证据 |
|---|---|
| 走 | 终点坐标、离目标多远、走了多少格 |
| 挖 | 那格前后方块名、背包里这种物品数量前后、掉落物捡到没有 |
| 放 | 那格现在是什么方块 |
| 合成 | 背包里该物品数量前后 |
| 拿/放 | 背包总量变化、容器内容 |
| 吃 | 饱食度前后 |
| 打 | 目标血量前后 / 目标还在不在 |
| 盖房 | 整栋逐格扫描跟图纸比对，列出差的格子 |

## 分期进度

- **一期（能活着）**：连接/重连、状态快照、七条保命反射、走跑跳潜行游泳、挖放用、吃睡、动作回读、事件攒批 —— 完成。
- **二期（能干活）**：全部完成——合成、箱子、熔炉、建筑图纸+施工+验收+断点续盖、死亡点记忆、附魔台、铁砧、村民交易、酿造台、种地、钓鱼、驯养。
- **三期（像玩家）**：全部完成——声音感知、目标记忆、小概率手滑、施工断点、**自主目标**（定计划 → 拆步 → 自己做 → 记账 → 卡住等大脑）—— 最小版完成；**战斗**（威胁排序、武器选择、吃/撤、苦力怕规避、弓放风筝）—— 完成；近战裸装 2v1 还是不稳（穿甲稳）；**节奏**（没事张望、动手前停顿、连续两天两夜后第三晚睡觉防幻翼）—— 完成；**地图记忆**（面包屑轨迹、沿轨迹回家/回矿）—— 完成。

## 游戏内聊天（耳朵和嘴，不做理解）

聊天这块归**大脑**：插件只负责把话原样送到，不猜意图。

- 主人在游戏聊天框里说话 → 插件把这条消息转给当前 DSH 会话（`sessionController.prompt`，一条用户消息），模型看到后自己决定怎么做：跟不跟、先做手上的还是先做这个、要不要记机器，然后自己用 `mc_chat say` 回话。
- 插件**不再**用关键词表判断"停下/跟着我/这是刷石机"；这些话全由模型理解。想让它跟人，模型自己调 `mc_move {player:"你的名字"}`；想记机器，模型自己调 `mc_mark`。
- 转不过去的时候（比如还没拿到会话号、或者 host 没有 `sessionController`）消息会进待办，等模型下次 `mc_chat read` 读走。
- `mc_chat`：`read` 读聊天和待办、`say` 回话、`pending` 看待办、`clear` 清待办。

**注意**：这依赖 host 提供 `sessionController.prompt` 且插件已经知道当前会话号（任何一次 mc_* 工具调用都会顺带记下来）。如果宿主环境没有这个服务，就退化成"待办 + 模型下次读"。

## 挂机（刷石机 / 农场）

- **它不认识建筑**：没有视觉，也不会猜"这是刷石机"。得先带它看一次：
  1. 走到机器旁边，看着出料口（准星对着那格）；
  2. `mc_mark {name:"刷石机", kind:"cobble_gen"}`——它会把"看着的那一格"记成出料口、把站的位置记成站位，再扫一圈附近有什么（漏斗、红石、水、岩浆……）一起存下来；
  3. 以后 `mc_afk {action:"start", place:"刷石机"}` 就能自己去挖。
  记一次，重启也还在（存在本机记忆文件里）。
- `mode:"mine"`：出料口那格一出现实心方块就挖掉，等它再长出来——刷石机、刷矿机都适用。
- `mode:"stand"`：站在点上，偶尔捡脚边的东西——铁傀儡农场、刷怪塔这类"站着就行"的。
- `mc_afk stop` 会报这次挖了多少；到时间（默认 30 分钟）自动停。
- 前提是**机器自己会再生**：插件只负责"出现了就挖"，不会帮你搭红石/流体。

## 地图记忆

- 每 2 秒把走过的点记成一条轨迹（4 格内只留最新一个点，最多 800 个），存在记忆文件里。
- `mc_map` 可以看最近走过哪些点；`mc_map {action:"route", place:"home"}` 会**沿着走过的路**走回去，轨迹帮不上忙（太短/离得太远）再交给寻路器。
- 用途：离家很远、寻路从零开始容易卡住；有走过的点就按点走。记忆里的地点（`mc_memory setPlace`）和轨迹是分开的，清轨迹不会丢地点。

## 节奏

- 没事的时候会慢慢转头张望（12 秒没活之后，每 3 秒有一次机会看一眼，幅度不超过约 80°）。
- **连续干活不休息**：干多久都不会因为"累"停下来。
- **连续两天两夜不睡，第三天入夜必须睡**：数的是"见过几次日出"（两次日出后的那个晚上），会自己找床躺下，睡完把目标接着做完；附近没床会报一声，但不会因此停活。这样第三晚之后就不会刷幻翼。
- 自主目标每做一步前会停 0.2~1 秒（不是机器，动手前会想一下）。
- 有活、开界面、打架的时候它一声不吭，绝不打扰。

配置在 `cordis.patch.yml` 的 `rhythm` 下（`enabled` / `idleLookAfterMs` / `lookChance` / `sleepAfterDays` / `bedSearchRadius`）。

## 功能方块

- **附魔台**：`mc_enchant {item:"diamond_sword"}`，会放物品和青金石，读回三个选项的等级，挑"等级够、青金石够"里最高的；不够会直接说，不会白放。附魔结果从背包里的实物读回。
- **铁砧**：`mc_anvil {item:"diamond_sword", name:"小鱼"}` 改名；也可以给 `item2` 合并/修理。产出先读出来再拿走，经验不够会说。
- **村民交易**：`mc_trade {listOnly:true}` 看列表，`mc_trade {tradeIndex:0, count:1}` 换。村民会乱走，插件会先走近再开界面；交易窗口开着时背包是副本，关掉之后才回读数量。

- **种地**：`mc_farm {action:"till", x,y,z}` / `{action:"plant", x,y,z, crop:"wheat"}` / `{action:"harvest", radius:8}`。只支持小麦、胡萝卜、土豆、甜菜，按 `age` 判断熟没熟，收完默认补种。
- **钓鱼**：`mc_fish {count:1}`。真服上钓到了三文鱼。
  - 两个坑：① 甩竿方向是服务端按当前视角算的，转头之后要等半秒再甩，不然钩落到背后；② 钩的落点比准星短，得瞄水池中间的水块（四面都是水的那种），瞄岸边会落在岸上。
  - 咬钩是自己盯的：`entity.fishing_bobber.splash` 声音或 6 个 splash 粒子，然后自己收杆；没用 `bot.fish()`（它在 26.2 上偶尔会误取消）。
- **酿造台**：`mc_brew {ingredient:"nether_wart"}`。槽位是 0/1/2 瓶子、3 材料、4 燃料；真服上 3 瓶水 → 3 瓶粗制的药水（potionId 0 → 3）。
- **驯养**：`mc_tame {item:"bone"}`。真服上喂一根骨头驯服了一只狼，验证方式看实体 metadata 里新增的主人 UUID（喂食成功但粒子不一定抓得到）。
  - 这里有个 26.2 的坑：服务器会检查"实体在视线里"，而 mineflayer 的 `activateEntity` 是 `lookAt(force=false)` 之后立刻发包，服务端视角还是旧的，交互就被拒。插件现在用 `interactEntity`（强制转头、等两个 tick 再发 Interact 包），喂食/驯服/开村民界面都走它。

- **打架**：`mc_fight {radius:12}`。按威胁排序（苦力怕最高），自动换背包里最好的剑/斧，血低于 12 先吃，低于 6 就退；苦力怕不近战，只后退。
  - **放风筝**：有弓和箭时，射箭的同时后退（退到 9 格就不再退，免得把它甩掉）；拉满一箭约 1.1 秒，两只僵尸基本摸不到人。
  - **近战**：打一下退半步（450ms）拖过攻击冷却；背包里有盾会举盾格挡；优先打死同一只再换目标（火力集中）。26.2 把攻击拆成了独立的 `attack` 包（`{entityId}`），mineflayer 的 `bot.attack` 发的是旧的 `use_entity`，打上去没反应——插件现在直接发 `attack` 包，`mc_use action=attack` 也一起修了。
  26.2 的 gamerule 也改名了：`doMobSpawning` → `spawn_mobs`，`doDaylightCycle` → `advance_time`；测试脚本里已经按新名字写。

实现分别在 `lib/stations.js`、`lib/farming.js`、`lib/fishing.js`、`lib/combat.js`；`mc_goal` 的步骤类型也加了 `enchant` / `anvil` / `trade`，可以排进自主目标。

## 自主目标

给它一个打算，它会在"手上有活、血够、没被围、没开界面"的时候自己一步步做；一次一步，做完记账，卡住就停下等大脑。

```js
mc_goal {
  action: "set",
  text: "挖 20 块石头，做一把石镐",
  steps: [
    { kind: "gather", block: "stone", count: 20 },
    { kind: "craft", item: "stone_pickaxe", count: 1 }
  ]
}
```

步骤类型：`gather`（挖够 N 个，掉落物进背包才算）、`craft`、`build`（图纸）、`goto`、`place`、`sleep`、`manual`（到这里暂停，等你接手）。

规则：失败重试，连续失败 3 次就把计划标成 `blocked` 并报事件；死了自动暂停；进度写在 `$DSH_HOME/mc-player/<host>_<user>.json`，重启接着做。`mc_goal` 的 get / pause / resume / clear 都在。

配置（`cordis.patch.yml` 的 `autopilot`）：`enabled`、`intervalMs`、`minHealth`、`pauseAtNight`、`maxAttempts`。

## 26.2 支持

26.2 的数据不在上游 `minecraft-data` 里（截至 2026-10 只到 26.1），所以插件自带一份：

```
vendor/26.2/              # 数据 + 安装器（约 6 MB）
npm run setup:26.2        # 装进 node_modules：拷 pc/26.2、合并 3 个 entry、补 4 处客户端版本登记
npm run check:26.2        # 只检查（缺就退出 1）
```

数据是从上游 PR #1219/#1298/#1339 的组合里取的，并用 26.2 官方 `server.jar --reports` 逐个核过（1196 方块 / 1537 物品 / 状态 id 与服务端一致）。细节和已知缺口在 `设计/mc-data-26.2/report/`。

两个注意：

- **`npm install` 之后要重跑 `npm run setup:26.2`**，否则 26.2 数据和 4 处版本登记会丢（1.16~26.1 不受影响）。
- 改的是 `node_modules` 里 4 个库的版本数组，**改完要重启 DSH** 才会生效；只连 1.x 不需要。
- 26.2 的用户名只能是字母/数字/下划线，默认改成了 `xiaojingyu`。

## 已知的坑

- mineflayer 的 `blockAt` 只认真 `Vec3`（内部会调 `pos.floored()`），插件里统一用 `vecAt()` 转换。
- 开着界面（箱子/熔炉）时不能走路；改了窗口状态记得 `mc_use action=close`。
- 服务器协议版本对不上时会连不上，`mc_connect` 里传 `version`（比如 `1.21.1`）。
- 掉落物要自己走过去捡——`mc_mine` 默认顺手捡，`pickup:false` 可以关。
- 一个 bot 一个进程。别用同一个号在别处再挂一个。
- 垫柱子（`mc_place tower:n`）必须跳起来、脚高过那一格，否则服务器判你占着那格直接拒。
- 转头是异步的：`bot.look(force:true)` 只是把目标角度排队，包要到下一个 tick 才发。所以"转头 → 等两 tick → 放"必须连在一起，不然服务器拿旧视角做射线，会判你够不着。放置和垫柱子都按这个顺序来。
- 顶面点击只能放"下半"的楼梯/半砖；要上半得点侧面上半格，或者站到下方点上面那块的底面。规划器会按这个找位置，找不到就报错。
- 寻路会为了够到目标自己垫方块（`allow1by1towers`），`mc_move` 的返回值里有 `blocksUsed`，垫了几块一眼能看到。
